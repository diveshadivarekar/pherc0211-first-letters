# PHerc. 0846A face renders (feasibility only)

Source: PHerc. 0846A, 2.403 um / 77 keV volume `20260319102732`, native crop z 4608-5632, y 15104-15616, x 12544-14080
(`data/real_scans/pherc0846a/native_crop_W0.h5`, not committed), with the `m7-L2` surface prediction (9.6 um voxels).
Generated by `scripts/probes/face_from_prediction.py` (command and git commit in `faces.json`).

**These are not submission evidence and show no ink.**

* The prize page lists the 9.362 um volume (`20250728152254`) as the eligible scan for this scroll; whether the 2.4 um volume may be used for
  First Letters is unconfirmed.
* Each face is 3.6-6.8 mm^2 (a qualifying region is 4 cm^2 = 400 mm^2) and is a height field over a plane, not an isometric flattening; no tifxyz
  mesh accompanies it. The assumption breaks on folds (step edges and streaks are artefacts).
* The window was picked by a planarity-only survey and turned out to be a delaminated, debris-filled periphery.
* Each PNG shows the same face at five offsets (-6, -3, 0, +3, +6 voxels) along its normal; the bar is 1 mm.

| `face_0.png` | 6.8 mm^2 | peak at -1 voxel | large voids, debris along edges |

Per-pixel ridge snapping saturates its +-10 voxel window at the 5th/95th percentiles, so fine detail on the snapped surface is not trustworthy.

## Ink-model check (2026-10-10) - no ink demonstrated

`scripts/probes/ink_on_faces.py` ran the fragment-trained U-Net (`ink_unet_20k.pt`, 54 keV / 3.24 um) on faces 0, 1, 3 and on copies of each
shifted +-30 voxels along the normal as controls (`ink_stats.json`). There is no ground truth for this scroll.

* The controls fire as much as the faces: share of pixels with P(ink) > 0.5 is 10.5 % on face 1 but 26.5 % on its +30 shift; face 0 is 25 % vs
  7.6 % / 14.3 % on its shifts. Flipping the depth direction swaps which orientation fires (face 1: 10.5 % normal, 43 % flipped; face 3: 30 % vs 0 %).
* The output is a few smooth saturated blobs ~1 mm across (`ink_check_face3_normal_UNVALIDATED.png`: page | P(ink) | P > 0.5), unrelated to the
  fibre texture, not stroke-like. Same behaviour as the Paris 4 labelled test (docs/INK_EVALUATION.md).

Conclusion: the model output on this scan is not evidence of ink. No letters or words are supported. M5 (OCR / translation) was deliberately not run:
its recogniser is trained on synthetic font renderings, so on these maps it would only produce fabricated text.
